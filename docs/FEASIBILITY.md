## Наблюдения для адаптера

- У карусели наблюдается список `ul` с позиционированными `li`; пустой служебный `li` не является медиа. Нельзя считать все дочерние элементы количеством слайдов.
- Видимые кнопки «Далее» и «Назад» отражали границы в этих двух примерах. Одного отсутствия «Далее» недостаточно для универсального доказательства полноты.
- Вторая карусель виртуализирует слайды: ранее просмотренные изображения удаляются из DOM при продвижении. Однократное чтение списка в конце теряет начало.
- Новый слайд может иметь пустой `currentSrc` сразу после клика. Нужна проверка готовности медиа с ограниченным ожиданием.
- Reload первой публикации сохранил последний слайд. Нельзя предполагать, что сбор начинается с первого изображения.
- В исследованных атрибутах медиа и контейнеров не обнаружены явные устойчивые item IDs или `aria-posinset`/`aria-setsize`. Не выводить ID из порядкового номера или временного адреса.
- Получение полного видеофайла, изменённая тестовая карусель и скачивание через Chrome Downloads с минимальными permissions остаются неподтверждёнными сценариями. Версия IAB не установлена; версия тестового Chromium из install smoke test не переносится на эти наблюдения.

Блокировка задачи 5: нет доказанного извлечения пригодного видеофайла и проверки Downloads API. До этого не добавлять предположительные video selectors или CDN allowlist.

Дополнительная проверка в тот же день: пользователь предоставил одиночное фото и Reel. Reel перенаправился с `/reel/` на `/reels/`; в DOM одновременно присутствуют несколько плееров, только один находится в текущем viewport. Нельзя выбирать первый video без привязки к активной публикации. Прямой HTTPS-источник в исследованном плеере не обнаружен; blob нельзя переименовать в MP4 и считать поддержанным файлом. Следующий исследовательский шаг — определить допустимый способ получения полного видеофайла; production video adapter до этого заблокирован.

Сохранять здесь только версии браузера/расширения, тип контента, шаги и PASS/FAIL. Не записывать аккаунты, исходные медиа-URL, HTML, токены или cookies.

## Сетевая диагностика Reel

1 октября 2026 года: через pageAssets обнаружены шесть наблюдаемых MP4-запросов, сгруппированных в два ресурса. Запросы имеют bytestart/byteend. Технические метаданные ресурсов указывают на DASH VP9 360p и отдельную HE-AAC аудиодорожку, обе длительностью 17 секунд. Эти метаданные ещё не подтверждены анализом скачанных контейнеров.

Экспорт наблюдаемых ресурсов через pageAssets завершился Failed to fetch. После явного разрешения пользователя подготовлен и запущен отдельный headless Chromium 153.0.8010.12 через Playwright: чистый временный профиль, probe extension только с permissions downloads, без host permissions и без переноса cookies. Проба снятия bytestart/byteend с тех же двух наблюдаемых адресов получила MIME video/mp4, однако обе загрузки interrupted / FILE_ACCESS_DENIED / 0 bytes. Defender event 1123 подтвердил запрет записи тестовому chrome.exe в work/reel-probe/downloads.

Вывод: выявлен способ доставки из двух DASH-дорожек; полный файл со звуком пока не получен. Не считать Downloads API успешным до complete и проверки файлов. Временная проба work/reel-probe/run.mjs не входит в production bundle. Безопасный отчёт work/reel-probe/evidence.json содержит только состояния, MIME и размеры. Временные URL не скопированы в репозиторий; исходный manifest браузерного инструмента находится в системной временной папке.

Следующее действие после разрешения точного тестового chrome.exe в Windows Defender: повторить пробу, проверить контейнеры/длительности обеих дорожек, оценить необходимость объединения аудио и видео. Автоматически не расширять permissions production-расширения и не обходить защиту папок.

## Повтор после разрешения Windows Defender — PASS скачивания дорожек

Пользователь сообщил проверить повторно. Обе загрузки через тот же probe extension завершились complete: video 866376 bytes, audio 128070 bytes. Permissions только downloads; host permissions отсутствуют; профиль чистый, cookies не переносились. Следовательно, для этих двух наблюдаемых адресов получение полных дорожек после удаления bytestart/byteend подтверждено. Это не доказательство универсальной стабильности CDN или привязки ресурсов к активному Reel.

ffprobe подтвердил VP9 video 360x640, 17.066667 s и отдельный AAC stereo 44100 Hz, 17.065215 s. Установленный локальный FFmpeg объединил дорожки с -c copy в MP4: 998688 bytes, 17.066667 s, оба потока присутствуют. Полное декодирование объединённого файла в null прошло с exit 0 без ошибок.

Это проверка технической возможности для одного Reel, не реализация расширения. Production-план предполагал один downloadUrl на элемент; для этого Reel нужны две дорожки и объединение. Локальный FFmpeg не является частью согласованного автономного расширения. Перед production video adapter нужно спроектировать объединение внутри браузера либо доказать доступность готового файла со звуком. Не добавлять зависимость от установленного FFmpeg молча. Проверка привязки сетевых ресурсов к активной публикации, высокого качества и изменённой карусели остаётся открытой.

## Объединение внутри расширения — PASS для локальных дорожек

1 октября 2026: добавлены remuxTracks на Mediabunny 1.61.0 и ручная страница merge.html (ссылка из библиотеки). Выбор двух локальных MP4, progress/cancel, сохранение MediaVault/merged.mp4 через Chrome Downloads с uniquify. Encoded packets копируются без перекодирования; исходные metadata tags не переносятся. Ограничения: 64 МиБ суммарного входа, 100000 пакетов, одна дорожка в каждом контейнере, допуск начала/конца 0.25 секунды. Вкладка должна оставаться открытой до окончания операции; beforeunload предупреждает о незавершённой операции.

В bundled extension проверены повреждённый вход (скачивание не начинается) и синтетические VP9/AAC дорожки (Chrome complete). Ранее сохранённые реальные дорожки также объединены самой страницей расширения: 992384 bytes; ffprobe VP9 360x640 17.066667 s и AAC 17.065215 s; независимое полное декодирование FFmpeg exit 0. FFmpeg не используется в runtime расширения. Исходные packet bytes проверены unit test на синтетических fixtures.

Автоматическое извлечение и сопоставление ресурсов с публикацией, передача пары дорожек в coordinator и полноценный Instagram Save по-прежнему не реализованы. Эта проверка подтверждает ручное объединение локальных дорожек, а не завершение первой версии расширения.
