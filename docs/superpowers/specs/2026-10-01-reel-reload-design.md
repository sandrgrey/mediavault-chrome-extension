# MediaVault: проект автоматического сохранения Reel

Статус: сценарий с одной перезагрузкой подтверждён пользователем 1 октября 2026. Реализация ещё не начата.

## Зачем менять сценарий

Reel использует blob-плеер с раздельными видео и звуком. На странице одновременно предзагружаются другие ролики. Выбор по порядку запросов или длительности ненадёжен. Временная проба подтвердила точную цепочку: активный video → blob → MediaSource → SourceBuffer → совпадающие байты сетевого MP4-ресурса.

Проверенный результат: H.264 720×1280 + AAC, 17,07 секунды, 4562563 байта. Полные дорожки доступны из контекста страницы с credentials: omit. Объединение выполнилось внутри расширения. Это доказательство для одного ролика, не универсальная поддержка.

## Предлагаемый сценарий

1. На странице конкретного Reel появляется Save с пояснением «Для сохранения страница будет перезагружена».
2. Клик резервирует операцию только для этой вкладки и публикации. Повторный клик не создаёт новую операцию.
3. Страница перезагружается один раз. Прокрутка и текущая позиция воспроизведения могут сброситься.
4. Новая страница получает одноразовое разрешение продолжить эту операцию. Только после этого начинается ограниченное наблюдение за MP4-данными.
5. Выбирается однозначно определённый активный плеер. Его видео- и аудиобуферы сопоставляются с содержимым полученных сетевых ответов, независимо от соседних роликов. Несколько подходящих источников означают отказ, а не угадывание.
6. Полные дорожки загружаются без cookies и объединяются без перекодирования. Итог передаётся Chrome Downloads, затем подтверждённый успех отражается в библиотеке.
7. Отмена, переход на другой пост, закрытие вкладки, превышение лимита или потеря контекста прекращают сбор. Автоматических повторных скачиваний нет.

До Save не копируются тела медиазапросов и не собираются временные media URL. Временные адреса и байты не записываются в базу или логи. Предварительная регистрация наблюдателей может учитывать только структуру плеера без медиасодержимого.

## Границы реализации

- Первый поддерживаемый поток: одиночный Reel по явному URL. Фото и карусели остаются отдельными задачами.
- MAIN-world мост связывает MediaSource с буферами; изолированный content script управляет операцией и проверяет все сообщения. Сообщение страницы само по себе не даёт права начать скачивание.
- Временная reload-резервация: tabId, publicationId, срок и одноразовый идентификатор. Старый documentId заменяется новым только при ожидаемой перезагрузке той же вкладки/публикации. Обычная смена документа отменяет сбор.
- Сбор ограничен 120 секундами; резервация — 150 секундами. Захват сетевых фрагментов имеет отдельный совокупный лимит 16 МиБ. Полные входные дорожки — до 64 МиБ. При достижении лимита — понятный отказ и освобождение буферов.
- Отдельные дорожки не должны появляться в пользовательской папке Downloads: готовый продукт сохраняет только объединённый MP4. Проба скачивала дорожки отдельно исключительно для проверки.
- Предпочтителен remux в изолированном контексте страницы с передачей итогового blob URL фоновому процессу. Доступность fetch из isolated world и скачивания такого Blob должна быть доказана тестом до закрепления транспорта. При несовместимости — вернуться к дизайну; не добавлять скрыто permissions/offscreen/сервер.
- Runtime-команды для blob-результата отделяются от обычных HTTP-загрузок. Проверяются текущий owner, операция, тип результата, размер и происхождение blob URL; URL не сохраняется в durable journal.
- Recovery и будущий coordinator используют общую очередь операций; recovery не переводит живую сессию с доступными URL в needs-user.
- Разрешения manifest не расширяются без доказанной необходимости. Нельзя переносить cookies, обходить вход или challenges.

## Проверки перед признанием рабочим

- Две соседние публикации, несколько предзагруженных плееров, смена маршрута, ручная прокрутка и изменение качества: отсутствие чужих дорожек.
- Однозначность сопоставления по медиаданным, отказ при одинаковых фрагментах из нескольких источников и при неполных данных.
- До клика: отсутствие копирования медиател и сохранения ссылок; после завершения/отмены: освобождение ссылок и буферов.
- Один reload на операцию, отсутствие циклов после worker restart, просроченный или чужой reload-intent не продолжает операцию.
- Отмена во время загрузки и remux; лимиты памяти/времени; отказ сети; восстановление Chrome Downloads без повторов.
- Проверка истинного содержимого MP4 и сохранения packet bytes; полный unit/integration suite; независимое ревью.

Подтверждённое решение: одна перезагрузка текущего Reel после Save допустима. Постоянный сбор медиаданных до клика не допускается.
